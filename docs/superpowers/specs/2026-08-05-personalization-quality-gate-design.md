# 리포트 개인화 품질 게이트 설계

## 왜 만드는가

오롭미의 가장 큰 실패 모드는 "해석이 부실하다"가 아니라 **"남과 결과가 똑같다"**이다.

2026-08-05 후기 1,479건 조사에서 확인된 사실:
- 이용자는 친구와 결과를 대조하거나, 성별·생년월일만 바꿔 재실행하는 **자체 검증을 실제로 한다.**
- 이 검증을 통과하지 못하면 반응은 "재미없다"가 아니라 **"사기"**로 규정된다.
- 앱스토어 부정 리뷰 1순위 축이 이것이며, 캡처·비교라는 물증이 생기는 순간 고발성 장문 후기로 이어진다.

반대로 후기를 쓰게 만드는 1순위 트리거는 "기대가 뒤집힌 순간"이다. 즉 개인화 품질이 후기의 근원이고, 후기가 매출의 근원이다.

현재 이 품질은 **사람이 눈으로 읽어야만** 판정할 수 있다. 프롬프트를 고칠 때마다 좋아졌는지 나빠졌는지 알 방법이 없다. 이 설계는 그것을 수치로 만든다.

## 무엇을 만드는가

세 개의 독립 단위로 나눈다. 각각 혼자 이해되고 혼자 테스트된다.

### 1. 유사도 측정 — `lib/quality/similarity.ts`

두 리포트 텍스트가 얼마나 겹치는지 0~1 수치로 반환하는 **순수 함수**. DB도 네트워크도 모른다.

- 방식: 문자 3-gram 자카드 유사도. 한국어는 형태소 분석 없이도 3-gram이 표절·템플릿 재사용 탐지에 충분히 작동하고, 외부 의존성이 0이다.
- 전처리: 이름·숫자를 제거한다. 이름이 다르면 자동으로 유사도가 낮아져 **진짜 문제(문장 템플릿 재사용)를 가리기** 때문이다. 이 전처리가 이 설계의 핵심 판단이다.
- 인터페이스:
  ```typescript
  export function normalizeForCompare(text: string): string
  export function similarity(a: string, b: string): number  // 0~1
  export function pairwiseSimilarity(texts: {id: string; text: string}[]): {a: string; b: string; score: number}[]
  ```

### 2. 클리셰 검출 — `lib/quality/cliche.ts`

프롬프트에서 금지한 표현이 실제 출력에 나왔는지 스캔하는 **순수 함수**.

- 금지 목록은 `lib/prompts/formats.ts`의 `ANTI_CLICHE` 규칙과 같은 내용을 정규식으로 표현한다. 두 곳에 흩어지지만, 프롬프트는 모델에게 주는 지시이고 이쪽은 결과를 검사하는 도구라 역할이 다르다. 목록이 어긋나지 않도록 이 파일 상단에 동기화 주석을 남긴다.
- 검출 대상: "겉은 차분한데 속은 열정" 계열 대비 구조, 콜드리딩 남발("~한 적 있죠?" 2회 초과), 전문용어 누출(십신 명칭).
- 인터페이스:
  ```typescript
  export interface ClicheHit { rule: string; excerpt: string }
  export function findCliches(text: string): ClicheHit[]
  ```

### 3. 점검 스크립트 — `scripts/check-quality.ts`

DB에서 완료된 리포트를 상품별로 모아 위 두 도구를 적용하고 결과를 출력한다.

- 같은 상품끼리만 비교한다 (평생사주와 궁합을 비교하는 건 의미가 없다).
- 출력: 상품별 최고 유사 쌍 3개와 점수, 클리셰 적발 건수, 판정(통과/경고).
- 임계값: 유사도 **0.35 초과 시 경고**. 근거는 "같은 상품·다른 사람이면 구조상 겹치는 어휘(섹션명, 존댓말 어미)가 있으므로 0.2~0.3은 정상이고, 그 이상은 문장 템플릿 재사용을 의심할 구간"이라는 판단이다. 첫 실행에서 실제 분포를 보고 조정한다 — 초기값은 가설이다.
- 종료 코드: 경고가 있으면 1. CI나 새벽 루프에서 실패로 잡을 수 있게.

## 데이터 흐름

```
reports 테이블 (status=done)
  → 상품별 그룹핑
    → normalizeForCompare (이름·숫자 제거)
      → pairwiseSimilarity → 최고 유사 쌍
      → findCliches → 적발 목록
        → 콘솔 리포트 + 종료 코드
```

## 오류 처리

- DB 연결 실패: 명확한 메시지와 함께 종료 코드 1. 조용히 통과하지 않는다.
- 비교 대상이 2건 미만인 상품: 건너뛰고 "표본 부족"으로 표시. 0건을 통과로 위장하지 않는다.
- 리포트 본문이 비어 있는 행: 경고로 집계 (생성은 됐는데 내용이 없는 건 그 자체로 문제).

## 테스트 전략

순수 함수라 전부 단위 테스트로 덮는다.

- `similarity`: 동일 텍스트 = 1.0, 완전히 다른 텍스트 ≈ 0, 이름만 다른 같은 템플릿 = 높은 값(0.9 이상) — **이게 이 도구의 존재 이유라 반드시 검증한다.**
- `normalizeForCompare`: 이름·숫자가 제거되는지.
- `findCliches`: 금지 표현이 있는 문장은 적발, 정상 문장은 통과.
- 스크립트 자체는 DB 의존이라 단위 테스트하지 않고, 실제 저장된 리포트로 1회 수동 실행해 검증한다.

## 하지 않는 것 (YAGNI)

- 임베딩·LLM 기반 의미 유사도 — 비용이 들고, 템플릿 재사용 탐지에는 n-gram으로 충분하다.
- 웹 대시보드 — 콘솔 출력이면 된다. 새벽 루프가 읽어서 보고한다.
- 자동 재생성 — 경고만 하고 판단은 사람이 한다. 자동으로 재생성하면 비용이 통제 불능이 된다.

## 성공 기준

1. 이름만 다른 동일 템플릿 두 개를 넣으면 0.9 이상이 나온다.
2. 실제 저장된 서로 다른 사주의 리포트들을 넣으면 0.35 미만이 나온다. (넘으면 프롬프트가 실제로 문제인 것이므로, 그 자체가 이 도구의 첫 성과다.)
3. 새벽 자율 루프가 이 스크립트를 돌려 결과를 일일 보고서에 남긴다.
