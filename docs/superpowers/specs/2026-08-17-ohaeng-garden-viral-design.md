# 오행 정원 — 바이럴 유입 시스템 설계

> 2026-08-17 브레인스토밍 확정본. 근거 조사: docs/doryeong-viral-research.md
> 결정자: 사장님(황선종) · 설계: 클로드

## 0. 목표와 원칙

- **1차 목표: 신규 유입 극대화** — 광고비 0원으로 사용자가 사용자를 데려오는 유입 엔진. 매출은 루프 밖 업셀로만.
- **확산 관계: 친구 무리(다인)** — 단톡방·인스타 스토리에 링크 하나를 뿌리면 여러 명이 들어오는 구조.
- 순위(서열) 요소를 1급 장치로 쓴다 — 단, **케미 순위만** (운세 순위 금지: 관계를 상하게 함).
- 전원 긍정 라벨 — 꼴찌도 웃어넘길 수 있는 결과만 존재한다.

## 1. 2단계 로드맵

| 단계 | 이름 | 규모 | 시점 |
|---|---|---|---|
| 1 | 케미 초대 링크 | S (하루) | 이번 주, 당근·토스와 병렬 |
| 2 | 오행 정원 | M~L (1~2주) | 당근 오픈·토스 재심사 제출 후, 1단계 지표 확인하며 |

1단계의 링크 생성·수신 랜딩·동적 OG·계측 코드가 그대로 2단계의 토대가 된다.

## 2. 1단계 — 케미 초대 링크 (검증 실험)

**플로우**: 무료 사주 결과 페이지 → "친구에게 우리 케미 물어보기" 버튼 → 공유 링크 생성 →
친구가 열면 "OO님과 너의 케미는?" 랜딩 → 생일 입력(기존 점진 폼 재사용, 로그인 없음) →
즉시 케미 점수 + 긍정 한 줄 (기존 오행 케미 엔진) → "나도 내 링크 만들기" CTA.

- 링크 페이로드: **별명 + 일간/오행 파생값만 인코딩. 생년월일 원본은 URL에도 서버에도 없음.**
- 여러 친구가 입력하면 링크 주인 화면에 **케미 순위가 쌓인다** — 기존 DB(Supabase)에 경량 테이블
  2개(chemi_links: 코드·별명·파생값 / chemi_replies: 별명·점수·라벨)만 추가. 순위 누적이
  2단계 정원의 핵심 검증 대상이므로 1단계부터 서버 저장으로 간다 (여전히 하루 분량).
- 동적 OG 카드 1종 (next/og): "OO님이 케미를 물어봤어요 — 생일만 넣으면 나와요 · 나도 보기"
- 계측: `utm_campaign=chemi_invite` + 이벤트 4종 (링크 생성 / 유입 / 입력 완료 / 재생성).

**판정 기준 (내부 가설, 1~2주 관찰)**: 유입→입력 ≥30% AND 입력→재생성 ≥15% → 2단계 착수.
미달 시 카드 카피·랜딩 문구 개선 후 재측정.

## 3. 2단계 — 오행 정원 (본편)

**플로우**: 방장이 생일로 정원 개설 → 전용 링크(/garden/[code]) → 친구가 별명+생일만 넣고 입장
(로그인 없음) → 자기 오행의 식물로 정원에 심어지고 방장과의 케미 점수+역할 라벨 획득.

### 핵심 장치 (우선순위순)

1. **정원 나래비 (케미 순위)** — 방장과 잘 맞는 순 순위표, 🥇🥈🥉 메달. 화면의 메인 구역.
   새 친구 입장마다 순위가 변동한다 — 기참여자의 재방문 이유.
2. **수집 미션 (오리지널)** — 정원에 부족한 오행이 마른 구역으로 표시:
   "이 정원엔 물(水)이 말랐어요 — 수 기운 친구를 데려오면 정원이 살아나요."
   초대가 막연한 부탁이 아니라 구체적 미션이 된다. 정원 완성도 % 표시.
3. **역할별 카운트** — "뿌리가 4명 — 사람 복이 두터운 정원" 식 요약 (도령의 '귀인 N명' 검증 공식).
4. **단비 배지** — 부족했던 오행을 채워 정원을 살린 친구에게 특별 칭호. 순위 밖의 영예.
5. **계절 테마** — 가을 정원·신년 정원 등 주기 갱신 (재소환 소재).

### 역할 라벨

방장 일간 기준 오행 상생상극(기존 엔진)으로 산출. **오롭미 오리지널 작명** (도령의 귀인/오른팔/
호랑이 선생 복제 금지). 전원 긍정. 라벨 세트는 구현 단계에서 카피라이팅.

### 데이터

- gardens: code, 방장 별명, 방장 팔자 파생값, 생성일, (선택) kakao_user_id
- garden_members: 별명, 팔자·오행 파생값, 케미 점수, 역할 라벨, 입장일
- **생년월일 원본은 서버에 저장하지 않는다** — 계산 후 파생값만.

### 카카오 로그인 (비대칭 원칙)

- **링크 받은 친구에게는 어떤 경우에도 로그인을 요구하지 않는다.**
- **방장에게만** 정원 생성 후 "카카오로 정원 저장하기" 옵션 — 내 정원 목록·재방문·관리.
  로그인 없이도 링크로 접근 가능 (로그인 = 순수 혜택).
- 기술: 카카오 OAuth (developers 앱 등록 — 사장님 카카오 계정 필요), 세션. 리포트 보관함 연결은 추후.

### 카카오 알림 (2차 확장 — 지표 확인 후, 비용 발생)

방장 재소환 전략 (사장님 설계):
- **메인(재방문 유도)**: "2등 순위가 변경되었어요" — 누군지 숨겨 호기심 갭으로 클릭 유도.
- **저강도(피로 시 전환)**: "2등이 OO님으로 변경되었어요" — 이름 공개형, 부담 없는 소식.
- 운영 안전장치: **하루 1회 묶음 발송** ("오늘 3명이 들어와 순위가 바뀌었어요"), 알림톡 템플릿
  사전 심사 통과 가능한 정보성 문구 유지.
- 비용: 카카오 비즈니스 채널 + 알림톡 건당 과금 → **집행 전 사장님 보고** (광고비 원칙 적용).

### 업셀 (루프 밖에서만)

정원을 전부 보여준 뒤에만: "이 친구와의 궁합 자세히 보기" → 기존 유료 상품.
990원대 브릿지 상품(예: 친구 1명과의 케미 한 줄 심화)은 **보류 — 별도 결정 사항**.

## 4. 하지 않는 것

- 링크 수신자에게 가입·로그인 요구 (루프 사망 요인 1순위)
- 부정적 결과·라벨 노출 (운세 순위 포함)
- 바이럴 루프 안에 유료 벽
- 생년월일 원본을 URL·화면·서버에 노출/저장
- 도령 표면 복제 (밤하늘/달/별 메타포, 귀인·호랑이 선생 라벨명)
- 네이티브 앱 개발
- 1단계 지표 검증 없이 2단계 착수

## 5. 보류 / 확장 아이디어 (결정 필요 시점에 재논의)

- 정원 대항전 (정원끼리 완성도 경쟁 — 단톡방 vs 단톡방)
- 990원 브릿지 상품
- "하반기 운 나래비" — 신년 시즌 카드로만 검토 (운세 서열 리스크 재평가 필수)
- 카카오 알림 고도화 ("OO님이 당신을 제쳤어요" 등 — 피로도 실험 후)

## 6. 성공 지표

- 1단계: K-근사 = (유입→입력 전환) × (입력→재생성 전환). 목표 30% × 15%.
- 2단계: 정원당 평균 참여자 수, 참여자→방장 전환율, 정원발 유입의 유료 전환율(기존 퍼널 대비).
